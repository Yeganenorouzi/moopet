> **وضعیت:** فاز ۰ — پیش‌نویس جهت تأیید
> **تاریخ:** ۱۴۰۵/۰۷/۰۱ (2026-09-23)
> **قاعده‌ی حاکم:** هیچ کدی نوشته نمی‌شود تا این سند تأیید شود. `getStaticPaths` مستقیماً از این تاکسونومی ساخته می‌شود.

## ۱. تصمیمات قطعی‌شده

| تصمیم | انتخاب | یادداشت |
|---|---|---|
| زبان اسلاگ | **انگلیسی** | خوانایی + سازگاری ابزار. جبران سئویی: کلمه‌ی کلیدی فارسی در title/H1/breadcrumb |
| دامنه‌ی فاز اول | **فقط تهران** | عمق به جای وسعت |
| منبع داده | نامشخص | فاز ۲ تعیین تکلیف می‌شود |
| عمق URL | حداکثر **۳ سگمنت** | `/[category]/[city]/[area]/` |

## ۲. چرا اسلاگ انگلیسی هزینه دارد و چطور جبران می‌شود

کاربر فارسی جست‌وجو می‌کند: `دامپزشکی سعادت آباد`

با اسلاگ فارسی، گوگل مسیر را بولد می‌کرد و CTR بالاتر می‌رفت. با اسلاگ انگلیسی این مزیت را نداریم، پس **تطابق کلمه‌ی کلیدی باید صددرصد در متن باشد**:

```
URL:        /vet/tehran/saadat-abad/
<title>     دامپزشکی سعادت آباد | ۱۲ کلینیک دامپزشکی در سعادت‌آباد تهران | موپت
<h1>        دامپزشکی‌های سعادت آباد
breadcrumb  موپت › دامپزشکی › تهران › سعادت‌آباد
```

⚠️ **قانون الزامی:** در `<title>` و `H1` باید هم شکل با نیم‌فاصله (`سعادت‌آباد`) و هم شکل با فاصله (`سعادت آباد`) پوشش داده شود، چون کاربران هر دو را تایپ می‌کنند. شکل بدون نیم‌فاصله در title، شکل استاندارد در H1.

### سه فرصت کلیدی

1. **`vet`** — سرترین کلمه‌ی حوزه. petlink دسته‌ی «دامپزشکی» ندارد، فقط زیرخدمات دارد. این یعنی head term بی‌صاحب است.
2. **`vet-24h`** — «دامپزشکی شبانه‌روزی» کوئری اورژانسی با بالاترین نیت خرید. رقیب فقط به‌صورت فیلتر (`tbTimes=41`) دارد، لندینگ ندارد.
3. **`vet-pharmacy`** — داروخانه دامپزشکی، دسته‌ی کاملاً غایب.

> **یادداشت مدل داده:** دسته‌های `service` صفت یک مرکزند (یک کلینیک هم‌زمان جراحی و واکسیناسیون دارد)، دسته‌های `business` نوع خود مرکزند. در دیتابیس: `listing.type` (یکی) + `listing.services[]` (چندتایی). هر دو صفحه‌ی لندینگ تولید می‌کنند اما منطق کوئری‌شان فرق دارد.

## ۴. تاکسونومی جغرافیایی تهران

### ⚠️ مهم‌ترین تصمیم این سند: اجتناب از انفجار محتوای تکراری

تهران سه محور جغرافیایی هم‌پوشان دارد:

- **مناطق شهرداری** (۱ تا ۲۲)
- **جهت‌ها** (شمال / جنوب / شرق / غرب / مرکز)
- **محله‌ها** (سعادت‌آباد، پونک، تهرانپارس…)

سعادت‌آباد هم‌زمان در «منطقه ۲» و «غرب تهران» است. اگر برای هر سه محور صفحه بسازیم، **یک لیست یکسان روی سه URL مختلف** می‌نشیند = duplicate content = کانیبالیزیشن.

### ✅ سلسله‌مراتب منتخب — فقط دو سطح ایندکس‌شونده

```
/[category]/tehran/                ← هاب شهر
/[category]/tehran/[zone]/         ← ۵ هاب جهت      (north|south|east|west|center)
/[category]/tehran/[neighborhood]/ ← برگ محله       (هم‌سطح با zone، نه تودرتو)
```

**چرا محله زیر zone تودرتو نیست؟** `/vet/tehran/west/saadat-abad/` چهار سگمنت می‌شود و لینک‌جویس را رقیق می‌کند. به‌جایش breadcrumb رابطه‌ی سلسله‌مراتبی را به گوگل اعلام می‌کند.

**اسلاگ‌های رزرو‌شده:** `north` `south` `east` `west` `center` — هیچ محله‌ای نباید این اسلاگ‌ها را بگیرد. در سطح دیتابیس باید constraint داشته باشد.

**مناطق شهرداری (۱-۲۲):** صفحه‌ی ایندکس‌شونده تولید **نمی‌کنند**. فقط به‌عنوان فیلتر در UI و فیلد داده در پروفایل مرکز. (اگر بعداً Search Console نشان داد «دامپزشکی منطقه ۵» حجم دارد، به‌صورت موردی اضافه می‌شود.)

## ۵. 🔒 قانون طلایی: آستانه‌ی ضد thin-content

این قانون باید مستقیماً در `getStaticPaths` پیاده شود:

```ts
// صفحه‌ی [category]/tehran/[neighborhood] فقط وقتی تولید می‌شود که
// حداقل ۳ مرکز فعال و تأییدشده داشته باشد
const MIN_LISTINGS_FOR_PAGE = 3;

if (listings.length < MIN_LISTINGS_FOR_PAGE) {
  // صفحه ساخته نمی‌شود → 301 به صفحه‌ی zone
  // /vet/tehran/gisha/  →  /vet/tehran/center/
}
```

| تعداد مرکز | اقدام |
|---|---|
| ۰ | صفحه ساخته نشود، ۳۰۱ به zone |
| ۱–۲ | صفحه ساخته نشود، ۳۰۱ به zone |
| ۳+ | صفحه‌ی ایندکس‌شونده کامل |

**چرا این مهم‌ترین قانون سند است:** بزرگ‌ترین اشتباه دایرکتوری‌ها ساختن هزاران صفحه‌ی خالی است. ۱۵ دسته × ۲۹ محله = ۴۳۵ صفحه‌ی بالقوه، که اگر داده نداشته باشیم اکثرشان خالی‌اند. گوگل این را به‌عنوان سایت بی‌کیفیت علامت می‌زند و **کل دامنه** آسیب می‌بیند، نه فقط آن صفحات.

با این قانون، سایت با ۵۰ صفحه‌ی پر شروع می‌شود و با رشد داده خودبه‌خود گسترش می‌یابد.

## ۶. نقشه‌ی کامل URL

| الگو | مثال | رندر | ایندکس |
|---|---|---|---|
| `/` | صفحه اصلی | static | ✅ |
| `/[category]/` | `/vet/` | static | ✅ |
| `/[category]/tehran/` | `/vet/tehran/` | static | ✅ |
| `/[category]/tehran/[zone]/` | `/vet/tehran/west/` | static | ✅ |
| `/[category]/tehran/[hood]/` | `/vet/tehran/saadat-abad/` | static | ✅ (اگر ۳+) |
| `/clinic/[city]/[slug]/` | `/clinic/tehran/parsian-vet-1042/` | static + ISR | ✅ |
| `/blog/[slug]/` | `/blog/dog-vaccination-guide/` | static | ✅ |
| `/search` | `/search?q=...` | SSR | ❌ noindex |
| `/panel/*` | داشبورد | SSR | ❌ noindex |
| `/auth/*` | ورود/ثبت‌نام | SSR | ❌ noindex |

### قوانین canonical و پارامترها

```
✅ ایندکس:    /vet/tehran/saadat-abad/
❌ noindex:   /vet/tehran/saadat-abad/?sort=rating
❌ noindex:   /vet/tehran/saadat-abad/?open=now
❌ noindex:   /vet/tehran/saadat-abad/?page=2   ← canonical به صفحه ۱
```

**هر URL دارای پارامتر ← `<link rel="canonical">` به نسخه‌ی بدون پارامتر + `<meta name="robots" content="noindex,follow">`**

این دقیقاً همان چیزی است که petlink رعایت نکرده و ۱۵۰ URL پارامتری در یک صفحه دارد.

## ۷. الگوی متادیتا

```
title:       {دسته فارسی} {محله} | {N} {دسته} در {محله} تهران | موپت
description: لیست {N} {دسته} در {محله} با آدرس، شماره تماس، ساعت کاری و نظرات کاربران.
             {نکته اختصاصی محله}. رزرو نوبت آنلاین در موپت.
h1:          {دسته فارسی}‌های {محله}
canonical:   https://moopet.ir/{category}/tehran/{hood}/
og:locale    fa_IR
html lang    fa-IR   dir="rtl"
```

⚠️ `{N}` عدد واقعی از دیتابیس باشد نه ثابت. اگر عدد تغییر کرد title هم تغییر کند (سیگنال تازگی).
⚠️ `{نکته اختصاصی محله}` باید یکتا باشد. تمپلیت تکراری = duplicate meta = هشدار Search Console.

## ۸. نقشه‌ی Schema.org

| صفحه | schema |
|---|---|
| همه‌ی صفحات | `BreadcrumbList` + `WebSite` + `Organization` |
| لندینگ دسته×مکان | `ItemList` (لیست مراکز) + `FAQPage` |
| پروفایل مرکز | `VeterinaryCare` یا `LocalBusiness` + `AggregateRating` + `OpeningHoursSpecification` + `GeoCoordinates` |
| بلاگ | `Article` + `BreadcrumbList` |

petlink **صفر** اسکیما دارد. این تنها بخشی است که می‌توان در آن سریع و قطعی برنده شد — rich result در SERP دیده می‌شود و CTR را بالا می‌برد.

⚠️ `AggregateRating` فقط وقتی درج شود که نظر واقعی وجود دارد. اسکیمای جعلی = پنالتی دستی گوگل.

## ۱۰. پیوست: خلاصه‌ی تحلیل رقیب

`petlink.ir` — ASP.NET Web Forms، TTFB ≈ ۹۵۰ms

| مورد | وضعیت |
|---|---|
| sitemap.xml | ❌ ندارد (soft 404 با کد ۲۰۰) |
